## 3. 변경 내용

### 3.1 planner 유형 수 검사 (`agents.py`, `pipeline.py`)
- 예전: 유형별 문항 수를 코드가 계산해 planner에 "정확히 이만큼"이라고 지시만 하고, 지켰는지는 보지 않음
- `plan_issues`: 문항 수, 유형별 문항 수(`type_counts` 결과와 정확히 일치), `item_id` 중복
- 어기면 문제 목록 + 이전 계획을 붙여 다시 요청 (최대 2번), 그래도 안 되면 `PlanError`로 멈춤
- 저장된 `plan.json` 재사용 시에는 다시 만들지 않고 경고만 (사용자가 고친 계획일 수 있음)
- `summary.json`에 `type_counts` (목표 / 계획 / 통과)

### 3.2 검증 없이 생성 (`pipeline.py`, `run.py`)
- `python run.py --course <과목> --no-verify`: solver·reviewer·수정 없이 문항당 generator 1번
- 규칙 검사는 비용이 없어 돌리되 기록만 (answers.md 검증 이력 "검증 안 함, 규칙위반 n개")
- M3 완료 기준 확인용이자 M5 실험의 `single` 조건(베이스라인)

### 3.3 기출 문항 단위 예시 (`schemas.py`, `exam_profile.py`, 프롬프트 3개)
예전에는 generator가 **기출 글자 전체(최대 3000자)를 문항과 상관없이 매번 똑같이** 받았음.
컴퓨터구성 기출은 2995자라 통째로 들어갔지만, 그림 쪽(상태도 등)은 빠졌고 어느 문제를 참고할지 알려 주지 않음.

| 단계 | 하는 일 |
|---|---|
| analyst | `ExamProfile.past_items`: 기출 문항마다 번호·유형·주제·배점·원문 위치(`refs`: 첫 줄·마지막 줄 번호, 그림 쪽 번호) |
| planner | `PlannedItem.past_refs`: 참고할 기출 문항 0~2개 |
| pipeline | `refs`가 가리키는 줄 범위의 원문을 **코드가 잘라** 전달 (모델이 옮겨 적지 않음). 그림 쪽은 이미지로 함께. planner가 안 고르면 같은 유형 기출, 문항 목록이 없는 예전 프로필은 예전 방식 |
| generator 지시 | 형식·난이도·말투만 참고, 문장·식·수치·질문 구성 사용 금지, 기출 파일을 근거로 쓰지 말 것 |
| 검사 | `past_items` 번호 중복, 없는 번호, 빈 위치 |

### 3.4 지엽적 검색 규칙 (`index.py`, `pipeline.py`)
- `Retriever.search_many(exclude=...)` 선택 인자 추가 (백엔드의 기존 호출은 그대로)
- `detail_level == "지엽적"`일 때만: 검색 쪽 수 = `retrieval_top_k`(4) × `detail_top_k_factor`(2), 앞 문항들이 통과하며 근거로 쓴 쪽을 `detail_reuse_limit`(1)번 이상이면 제외
- "핵심 위주"·"중간"은 그대로

### 3.5 베끼기 검사 (`checks.py`, `agents.py`, `prompts/reviewer.md`)
- 규칙 검사 `copy_issues`: 문제 본문·선지와 **기출 문항 전부**의 글자 3개 조각 겹침(짧은 쪽 기준) ≥ 0.25면 수정 요청
- reviewer: generator가 참고한 기출 원문을 프롬프트 끝에 붙여 "같은 질문을 표현·숫자만 바꾼 것"이면 revise
  - 프롬프트 파일에 빈칸(`{{...}}`)을 만들지 않고 코드에서 붙임 → 같은 프롬프트 파일을 쓰는 백엔드는 영향 없음
- 명세 §6의 "임베딩 유사도 > 0.9" 기준을 바꿈 (근거는 §4.3)

### 3.6 헛 호출 제거 (`pipeline.py`)
- 예전: 마지막 시도에서 규칙 위반·revise가 나와도 generator를 한 번 더 부르고, 그 결과는 검사 없이 버림 (11-19 q1: 약 12초, 9천 토큰)
- 마지막 시도면 바로 멈춤. 문항당 generator 호출 = 최대 시도 수 (테스트)
