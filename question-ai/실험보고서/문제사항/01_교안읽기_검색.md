## R-01. 쪽 제목 추출 오류 — **해결**
- **현상**: 컴퓨터구성 교안에서 진리표·수식·글머리 기호 문자가 쪽 제목으로 뽑힘. planner 주제 목록과 검색어가 엉터리가 됨
  - 예: Chap1-2_rev p.14 제목 `Truth table s = x'y + xy' = x y c = xy x y c s 0 0 0 …` (실제: Half Adder)
  - 11-19 실행 q4 검색어가 `J K Q(t+1) J Q 0 0 Q(t) No change…` (진리표 조각)
- **원인**: "쪽 전체에서 가장 큰 글씨"를 제목으로 봄. 제목이 도형으로 들어간 교안 4개(Chap1-2_rev, chap1-3, chap2-1, chap2-2)는 PDF에 제목 글자가 아예 없음
- **한 일**
  - `17b3cfc` 위쪽 25%만 제목 후보, 단어 없는 줄·글머리 기호 문자 제외, 제목 없는 쪽은 앞 제목 이어받기
  - `69d19cb` 제목을 못 뽑은 쪽이 절반 이상인 PDF는 build_index 때 Gemini로 위쪽 띠를 읽어 `index/titles.json`에 저장
- **결과**: 단어 없는 제목 43 → 13 → 0 (컴퓨터구성 129청크). 컴퓨터네트워크는 변화 없음
- **근거**: [11-20 보고서](../2026-11-20_교안제목추출문제.md), 11-19 보고서 §5

## R-02. 제목이 검색에 쓰이지 않음 — **해결**
- **현상**: Gemini로 제목을 읽은 뒤에도 "Half Adder" 검색 시 해당 쪽이 3위 밖
- **원인**: 검색(임베딩·BM25)은 본문 글자만 봄. 도형 제목 쪽은 본문에 제목 글자가 없음
- **한 일**: `69d19cb` 본문에 제목이 없으면 앞에 붙여 검색 (`search_text`). 인덱스 지문도 이 글 기준
- **결과**: Half Adder, JK Flip-Flop, Don't-Care Conditions, 멀티플렉서 모두 1~2위
- **근거**: 11-20 보고서 §2.3, §3.2

## R-03. 그림 쪽 본문이 검색에서 빠짐 — **미해결**
- **현상**: 글자가 20자 미만인 쪽은 청크를 만들지 않음 → 검색 대상이 아님
  - 컴퓨터구성 159쪽 중 **30쪽** 제외, 컴퓨터네트워크는 13쪽을 PNG로만 저장
  - "State Assignment"(chap1-3 p.26), "Map Simplification"(Chap1-2_rev p.4, chap1-3 p.2) 검색 실패
- **원인**: PyMuPDF는 PDF에 글자로 저장된 것만 꺼냄. 그림·도형 속 내용은 못 읽음. PNG는 저장만 하고 에이전트에 안 보냄 (이슈 #3 결정)
- **제안**: 제목과 같은 방식으로 build_index 때 한 번만 이미지 모델로 본문을 글로 바꿔 저장
- **근거**: 11-19 보고서 §5, 11-20 보고서 §4, 11-21 지엽적 규칙 검색 확인

## R-04. 본문이 의미 없는 글자 나열 — **미해결**
- **현상**: 진리표·회로 쪽은 글자는 나오지만 `x y c s 0 0 0 0 …`처럼 숫자 나열이라 검색·출제에 도움이 안 됨
- **제안**: R-03의 이미지 읽기 대상에 포함할지 기준 필요 (글자 수 + 단어 비율 등)
- **근거**: 11-20 보고서 §4

## R-05. 글자 기반 제목이 엉터리인데 걸러지지 않는 쪽 — **미해결**
- **현상**: Chap4_1 p.21 제목 `in 1, 0 0 0 0`. 글자로 "뽑았다"로 처리돼 Gemini 대상이 아님
- **제안**: 제목 품질 검사 기준 (숫자 비율 등)
- **근거**: 11-20 보고서 §4

## R-06. 정상 교안에서 제목 없는 쪽은 앞 제목을 이어받기만 함 — **미해결 (사소)**
- **현상**: Chap1-1·Chap3·Chap4_1 각 1쪽. 이어받은 제목이 틀릴 수 있음
- **제안**: 해당 쪽만 Gemini로 읽기 (3번 호출)
- **근거**: 11-20 보고서 §4

## R-07. 같은 제목의 표기 차이 — **미해결 (사소)**
- **현상**: chap2-2 p.22 `메모리 - ROM` / p.23 `메모리 – ROM` (하이픈 종류). planner 주제 목록에서 다른 제목으로 보임
- **근거**: 11-20 보고서 §4

## R-08. 한국어 검색어로 영어 교안을 잘 못 찾음 — **해결**
- **현상**: 컴퓨터네트워크(영어 교안)에서 한국어 검색어 5개 중 임베딩 4/5, BM25 3/5. 표지 쪽이 결과 9개 목록 중 7개에 끼어듦
- **원인**: 검색어 언어와 교안 언어가 다름. 점수 기준선으로는 거를 수 없음 (정답과 표지 차이 0.004)
- **한 일**: `fb9573b` planner가 교안 제목을 번역 없이 복사한 `source_titles`를 검색어로 사용
- **결과**: "HTTP 비상태 특성" 관련 쪽 0개 → 4개
- **근거**: 11-19 보고서 §4.3

## R-09. "지엽적" 검색을 넓히면 관련 없는 쪽이 섞임 — **확인 필요**
- **현상**: 검색 쪽 수를 8쪽으로 늘리면 뒤쪽에 표지(chap2-2 p.1), 엉터리 제목 쪽(Chap4_1 p.21)이 들어옴
- **원인**: 범위를 넓히는 대가. 교안에 쪽이 적은 주제는 관련 쪽이 금방 바닥남
- **제안**: 실제 "지엽적" 과목으로 실행 후 `detail_top_k_factor` 조정
- **근거**: 11-21 보고서 §5

## R-10. 첫 검색 때 임베딩 모델 불러오기 30~80초 — **미해결 (서버에서는 한 번)**
- **현상**: 실행마다 첫 문항 시간이 길어짐 (11-21: q1 109.5초 중 생성 31초)
- **원인**: torch 등 라이브러리 불러오기 21~33초 + 모델 10~12초 (11-19 측정)
- **제안**: 계속 켜져 있는 서버에서는 처음 한 번만 듦. 필요하면 ONNX 검토
- **근거**: 11-19 보고서 §4.4, 11-21 보고서 §4.2
