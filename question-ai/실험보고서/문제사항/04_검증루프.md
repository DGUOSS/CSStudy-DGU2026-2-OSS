## V-11. "같은 질문" 판정이 엄격해 정해진 모양의 단원이 통과하기 어려움 — **해결 (기준 변경)**
- **현상 (`20261121-162212`, M4 완료 확인 실행)**: 4문항 중 2문항이 3번 모두 "기출과 같은 질문"으로 revise → 제외 → 보충. 출제 정답은 맞았음 (q1 코드 검산 통과)
  - q1 카르노 맵: 3번 모두 "기출 2번과 같은 질문 (소문항 3개 중 2개)". generator가 수정 지시를 받고도 "Σm+d → 최소 SOP" 틀을 못 벗어남
  - q4 메모리: "RAM과 ROM 차이" 소문항을 기출 6번(RAM과 Flash 차이)과 "메모리 쌍만 다른 같은 과제"로 판정 — 지나치게 엄격하다고 볼 여지
- **영향**: 819초, 호출 44번, 36만 토큰 (보충 2번). V-04 이후 판정은 일관되지만 기준이 엄격함
- **선택지였던 것**: "절반 이상" → "모든 소문항이 같을 때"로 완화 / 정해진 모양의 단원은 같은 과제 허용 / generator 수정 지시 강화
- **통과한 문항 분석**: 통과한 4문항은 기출과 같은 개념을 방향 뒤집기(10진→비트열 대신 비트열→10진), 다른 결과(간격 최소·최대 대신 상대 오차), 규모·부품 바꾸기(2×1→4×1 MUX), 응용·추적(입력 시퀀스 추적)으로 바꿨음. 대부분 2~3번째 시도에 통과
- **결정 (2026-11-21)**: **시험 문항 수의 25%까지 기출과 같은 질문(숫자만 바꾼 것 포함) 허용.** 다른 문항이 충분히 기출을 바꿨다면 한 문항쯤은 기출 변형이어도 괜찮다는 판단. 평균 점수 대신 "허용 개수"로 한 이유: 문항을 순서대로 만들어서 평균은 끝나야 알 수 있음
- **한 일**
  - `Review.past_same`·`past_total` (같은 과제인 소문항 수 / 비교한 소문항 수). reviewer는 같은 질문이라는 이유만으로 revise하지 않음
  - pipeline: 통과 판정인데 같은 질문(같음 비율 ≥ 0.5 또는 글자 겹침 ≥ 0.25)이면 허용 개수가 남았을 때 통과·"기출 변형"으로 기록, 다 썼으면 수정 요청 (선착순)
  - 글자 겹침 규칙 검사도 허용 개수가 남아 있으면 막지 않음
  - answers.md "기출 변형", report.md 표·문항 제목, summary.json `past_variants`·`past_variant_limit`
  - 설정: `past_variant_ratio: 0.25`, `past_same_ratio: 0.5`. 명세 §10 변경
- **실행 확인 (`20261121-172152`, 계획·첫 생성은 162212와 같음)**: 4/4 통과, 보충 0번. q1 카르노 맵이 "기출 2번 변형 — 소문항 2/3 같음"으로 첫 시도에 통과 (162212에서는 3번 모두 탈락). q2는 소문항 1/2 같음 → 허용 개수를 다 써서 수정 요청 → 2번째에 통과. q4 메모리도 2번째에 통과
  - 모델 호출 22번(새 호출 13 + 캐시 9), 282초 — 162212는 44번, 819초 (첫 생성이 캐시라 시간은 단순 비교 불가)
- **남은 것**: 같음 비율 기준이 "0.5 이상"이라 소문항 2개 중 1개만 같아도 같은 질문으로 셈 (q2). 너무 엄격하면 `past_same_ratio`를 올리면 됨
