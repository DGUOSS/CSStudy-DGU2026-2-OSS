## G-04. 기계적 계산 문제의 정답 오류 — **일부 해결**
- **현상**
  - 11-19 q1: f = Σm(0,2,3,5,7,8,10,11) + d(4,15). 1차 출제 정답 SOP·POS 모두 틀림, 이후 "최소" 조건 못 맞춤 → 실패
  - 11-21 `112142` q1 (검증 없음): `F = A'B + BC + AC'`에서 `BC`를 중복 항으로 보고 지움. 입력 A=B=C=1에서 원식과 다름. 실제 최소식 `B + AC'`
- **원인**: LLM이 불 대수 간소화를 안정적으로 못 함 (합의 정리 대상 항을 잘못 고름)
- **한 일**: `b0ba582` 코드 검산 (`verify.py`, AI 호출 없음)
  - generator가 `Question.verifications`에 소문항별 검산 거리(원래 함수·값 + 정답)를 적음
  - 불 식: 모든 입력 대입, SOP/POS 형태, "최소"면 Quine-McCluskey로 최소 리터럴 수 계산해 비교. IEEE 754, n비트 보수·부호-크기
  - 틀리면 반례 입력과 함께 수정 요청. 맞으면 reviewer에게 알림 (V-01)
- **결과**
  - 기존 사례 재현: 11-19 q1 시도별 판정, `112142` q1 오답(A=B=C=1 반례) 모두 보고서와 같게 판정
  - `20261121-121035`(검증 없음): 4문항 중 3문항이 검산 거리를 적음, 불 식 4개·IEEE 754 1개 모두 맞음
  - `20261121-121425`(검증): 검산 틀림 0건. q1 3번 시도 모두 검산 통과
- **남은 것**: 검산 종류가 3가지뿐 (MUX 입력, 개수, 상태표, 진수 변환 등은 안 됨). G-07
- **근거**: 11-19 보고서 §4.6, 11-21 보고서 §4.4

## G-08. gpt를 generator로 쓰면 정답 오류·모순 문제가 많음 — **관찰 (1세트)**
- **현상 (모델 바꿔 넣기 실험 `실험_20261121-182826`, generator gpt-5.4-mini)**
  - q1 카르노 맵: 출제 정답 SOP `a'b'+bc'+ac`가 원래 함수와 입력 10개에서 다름. 3번 모두 같은 식으로 코드 검산 실패 → 탈락
  - q2 부동소수점: 25.0을 `0x41840000`으로 적음 (맞는 값 `0x41C80000`). 코드 검산이 잡아 1번 고친 뒤 통과
  - q3 MUX: 함수가 4비트 홀수 패리티 Σm(1,2,4,7,8,11,13,14)라 MUX 입력이 C⊕D가 되는데, 문제는 "C, D와 그 보수, 상수만으로 표현하라"고 함 → 조건과 정답이 모순
- **교차 검증 사례**: q3 요청을 solver 자리에 따로 보냈을 때(V-13 확인 중) gemini는 "조건에 모순이 있을 수 있음"으로 모호 표시(confidence 0.90), 같은 회사인 gpt는 모순을 못 보고 confidence 0.98. 실험 가설(다른 회사 모델이 더 잘 잡음)과 맞는 사례지만 1건
- **참고**: 같은 계획에서 gemini generator는 코드 검산 실패 0번, claude generator는 1번(최소식 아님)
- **한계**: 1세트·4문항. 모델 저가 버전(mini)끼리 비교
