## 1. 문제 상황

### 1.1 무엇이 문제였나
쪽 제목은 두 군데에 쓰인다.
- **planner의 주제 목록**: planner가 이 목록에서 주제를 고르고 `source_titles`로 그대로 복사한다.
- **검색어**: `source_titles`가 그대로 교안 검색어가 된다 (11-19 보고서 §3.4).

그래서 제목이 틀리면 **엉뚱한 주제가 출제 계획에 들어가고, 근거 쪽도 엉뚱하게 찾아진다.**
11-19 컴퓨터구성 실행(`first`)에서 q4의 검색어가 진리표 내용이 된 것이 이 문제였다 (11-19 보고서 §5).

### 1.2 왜 생겼나 — PDF에서 글자를 꺼내는 방식의 한계
```
PDF ─①글자 꺼내기(PyMuPDF)─▶ 텍스트 ─②임베딩(e5)─▶ 벡터 ─▶ 검색
```
- ①은 PDF 안에 **글자로 저장된 것만** 꺼낸다. 이미지·도형 속 글자는 못 읽는다.
- ②는 ①의 텍스트를 받아 숫자로 바꿀 뿐, 이미지를 보지 못한다.
- 예전 제목 규칙: "쪽 전체에서 가장 큰 글씨". 다음 두 경우에 틀린다.

| 경우 | 실제 모습 | 예전 결과 |
|---|---|---|
| 제목이 글자인데 가운데에 더 큰 진리표·수식이 있음 | Chap3, Chap4_1 등 | 진리표 숫자·수식이 제목이 됨 |
| **제목이 도형(그림)으로 들어감** | Chap1-2_rev, chap1-3, chap2-1, chap2-2 | 위쪽에 꺼낼 글자가 없어 본문의 수식·기호가 제목이 됨 |

예전 제목 예 (Chap1-2_rev):
- p.2 `F = 𝑥+𝑦′𝑧 F = 𝑥′𝑦′𝑧+𝑥𝑦′𝑧′+ …` (실제 제목: Boolean Algebra)
- p.8 `   ` (글머리 기호 글꼴 문자. 실제: Don't-Care Conditions)
- p.14 `Truth table  s = x'y + xy' = x y c = xy x y c s 0 0 0 …` (실제: Half Adder)

### 1.3 파일별 상태 — 위쪽 글자에서 제목을 못 뽑은 쪽 비율

| 파일 | 쪽 | 못 뽑음 |
|---|---|---|
| Chap1-1 | 18 | 1 (6%) |
| **Chap1-2_rev** | 24 | **24 (100%)** |
| **chap1-3** | 30 | **30 (100%)** |
| **chap2-1** | 19 | **19 (100%)** |
| **chap2-2** | 23 | **23 (100%)** |
| Chap3 | 24 | 1 (4%) |
| Chap4_1 | 21 | 1 (5%) |
| 컴퓨터네트워크 3개 | 111 | 0 (0%) |

→ 도형 제목 교안 4개는 **글자로는 해결 불가**. 나머지는 규칙만 고치면 된다.

## 2. 해결

### 2.1 글자 기반 규칙 수정 (`pdf_parser.py`, `chunker.py`)
- 제목 후보는 **쪽 위쪽 25%** 안의 글자만 (가운데 진리표·수식 제외)
- **단어(글자 2개 이상 연속)가 없는 줄은 제목이 아님** (숫자·기호뿐인 줄 제외), 글머리 기호 글꼴 문자(U+E000~F8FF) 제거
- 제목 크기와 **같은 크기의 조각만** 이어 붙임 (더 큰 기호 조각이 제목 앞에 붙던 문제 — 테스트에서 발견: `1 = 0 + 1 Half Adder`)
- 위쪽에 제목이 없는 쪽은 **같은 파일의 앞 제목 이어받기** (진리표·연습문제 쪽이 앞 개념 쪽과 같이 검색되게)

### 2.2 도형 제목은 Gemini로 읽기 (`ingest/vision_titles.py`, `prompts/title_reader.md`)
- **대상**: 위쪽 글자에서 제목을 못 뽑은 쪽이 **절반 이상인 PDF**만, 그 파일의 모든 쪽 (이번에는 4개 파일 96쪽)
- 쪽 **위쪽 25% 띠**만 PNG로 잘라 보냄. 모델 `gemini/gemini-3-flash-preview` (`config.yaml` `models.title_reader`)
- 지시: 보이는 글자 그대로, 번역 금지, 쪽 번호·로고·수식 제외, 제목 없으면 빈 칸
- **`build_index` 때만 부르고 `index/titles.json`에 저장**. 출제(`load_chunks`)는 이 파일만 읽음 → 출제 중 추가 호출 없음, 인덱스와 제목이 항상 같음
- 옵션: `--no-vision-titles`(부르지 않음), `--reread-titles`(다시 읽기)

띠 OCR 방식 비교 (2026-11-19, 띠 10장):

| 방식 | 맞음 | 비고 |
|---|---|---|
| **Gemini** | **10/10** | API 호출 |
| PaddleOCR | 6/10 | 쪽당 23초, 별도 가상환경 필요 |
| EasyOCR | 3/10 | |

### 2.3 검색에 제목 반영 (`ingest/index.py`)
- 제미나이로 제목을 읽고 나서도 **검색은 여전히 실패** — 검색은 본문 글자만 보는데, 도형 제목 쪽은 본문에 제목 글자가 없음
  - 예: Chap1-2_rev p.14 본문 = `x y c s 0 0 0 0 … Truth table s = x'y + xy'` ("Half Adder" 글자 없음)
- **본문에 제목이 없으면 제목을 앞에 붙여** 임베딩·BM25에 넣음 (`search_text`). 본문에 이미 제목이 있는 교안은 변화 없음
- 인덱스 지문(해시)도 이 글 기준 → 제목이 바뀌면 오래된 인덱스를 쓰지 않음

## 4. 남은 문제

| 문제 | 근거 | 제안 |
|---|---|---|
| **그림 쪽 본문이 검색에서 빠짐** | 컴퓨터구성 159쪽 중 **30쪽**이 글자 20자 미만이라 청크 없음. "State Assignment"(chap1-3 p.26) 검색 실패 | 이슈 #3: 그림 쪽 본문을 이미지 모델로 글로 바꿔 저장 (제목과 같은 방식: build_index 때 한 번, 결과 저장) |

## 5. 확인하지 못한 것
- 제목 수정 후 **전체 실행(출제까지)** 은 아직 안 함. planner 주제 목록·문항 근거가 실제로 좋아졌는지는 M3 실행에서 확인
- 검색 확인은 검색어 5개, 1회. 교안 내용을 아는 사람의 검토는 아직
- Gemini 제목 읽기의 정확도는 96쪽 결과 목록을 훑어본 것, 띠 이미지 2장(Chap1-2_rev p.1, p.6)과 "없음" 쪽 3장의 이미지 확인까지. 96쪽 전부를 이미지와 대조하지는 않음
