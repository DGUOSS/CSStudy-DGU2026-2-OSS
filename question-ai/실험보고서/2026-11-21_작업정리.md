## 4. 오후 작업

### 4.1 코드 검산 (`verify.py`) — G-04, V-01, V-03
- **문제**: LLM이 불 대수 간소화를 자주 틀림 (오전 `112142` q1 오답, solver도 같은 유형을 반복해서 틀림)
- **방식**: generator가 `Question.verifications`에 소문항별 검산 거리(원래 함수·값 + 정답)를 적고, 코드가 확인
  - 불 식: 모든 입력 대입, SOP/POS 형태, "최소"면 Quine-McCluskey로 최소 리터럴 수 계산
  - IEEE 754 단정밀도·배정밀도, n비트 2의 보수·1의 보수·부호-크기
  - 표기: `A'`, `\overline{A}`, `\bar A`, `¬`, `⊕`, LaTeX, `F(A,B,C) =` 접두어
- **틀리면**: 반례 입력과 함께 수정 요청 (예: "A=1, B=1, C=1에서 원래 1 → 식 0")
- **맞으면**: reviewer에게 검산 결과(원래 함수 포함)를 알려, 풀이자 오답을 출제 오류로 오해하지 않게
- **확인**: 11-19 q1 시도별 판정, 오전 q1 오답을 보고서 기록과 같게 판정. 실제 생성에서 검산 거리 5개 작성·모두 맞음. 검증 실행에서 reviewer가 "출제 정답은 검산 결과 맞다, 불일치는 풀이자 오류"로 판단
- **한계**: 검산 종류 3가지뿐 (MUX 입력·개수·상태표 등은 안 됨). 검산할 수 없는 것을 억지로 적는 경우가 있어 코드가 "의미 없음"으로 거름 (G-07)

### 4.2 실패 문항 보충 — V-07, P-08
- **문제**: 검증에서 떨어진 문항이 빠지면 최종 시험지 유형 비율이 깨짐 (`115412`, `121425` 모두 서술형 0개)
- **방식**: 실패 문항마다 planner에 같은 유형·다른 주제로 1문항 다시 계획 (실패 이유·이미 쓴 주제 전달). `q4-r1`처럼 번호, 배점 이어받음. 보충 문항이 또 실패하면 다시 보충하지 않음. 원래 `plan.json`은 그대로, 보충 포함 계획은 `plan_final.json`
- **교안 밖 주제**: planner·generator에 "기출 주제·개념이라도 교안에 없으면 고르지/넣지 않는다" 추가
- **결과 (`124610`)**: q4(RAM vs Flash) 실패 → `q4-r1` "동기식 순차 회로 상태도 최적화" 1번에 통과 → **처음으로 최종 유형 비율 = 목표 (계산 3·서술 1)**
- **남은 것**: planner가 RAM(교안에 있음)을 고르면서 참고 기출로 6번(RAM vs Flash)을 같이 골라, generator 1차에 Flash가 다시 들어감

### 4.3 reviewer 판단 일관성 — V-04
- **측정**: `115412` q1 2차·3차 문항을 **입력 그대로** reviewer에 3번씩 다시 보냄 → 같은 질문 판단·판정이 바뀜. 시도마다 문항이 달라서가 아니라 판단 자체가 흔들림
- **원인**: Claude는 temperature를 받지 않음 / `Review` 칸 순서가 판정 → 이유 (solver V-02와 같은 구조) / 직전 지적을 모름
- **바꾼 것**: 칸 순서 비교 → 지적 → 판단 항목 → 판정 / 같은 질문 판단 절차 (소문항별 과제 비교, 절반 이상 같으면 같은 질문) / 수정한 문항 재검토 때 직전 지적을 주고 "고쳐짐/안 고쳐짐"부터

| 문항 | 바꾸기 전 (원래 + 3번) | 바꾼 후 (3번) |
|---|---|---|
| 2차 문항 | "같은 질문" 1번 / "아님" 3번 | 3번 모두 "아님" (같음 1/3) |
| 3차 문항 | pass 3번 / revise 1번 | 3번 모두 revise "같은 질문" (같음 2/3) |

- **남은 것**: 판단이 더 엄격해짐 (원래 통과한 문항이 이제 revise). 한 문항 × 3번 측정

### 4.4 그림 교안 쪽 읽기 — R-03
- **문제**: 글자가 20자 미만인 쪽은 청크가 없어 검색·출제에 안 쓰임 (컴퓨터구성 30쪽). 확인해 보니 **글자를 도형으로 바꿔 넣은 슬라이드**였음

- **결과**
