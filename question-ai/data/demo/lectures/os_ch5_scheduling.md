## CPU 스케줄링 개요
CPU 스케줄러는 준비 큐(ready queue)에 있는 프로세스 중 하나를 선택해 CPU를 할당한다.
선점형(preemptive) 스케줄링은 실행 중인 프로세스로부터 CPU를 빼앗을 수 있고, 비선점형은 프로세스가 종료하거나 대기 상태로 갈 때까지 CPU를 유지한다.
디스패처는 문맥 교환, 사용자 모드 전환, 프로그램 재시작 위치로의 점프를 담당하며, 이 시간을 디스패치 지연(dispatch latency)이라 한다.

## 스케줄링 기준
- CPU 이용률(utilization), 처리량(throughput): 단위 시간당 완료된 프로세스 수
- 총 처리 시간(turnaround time) = 완료 시각 − 도착 시각
- 대기 시간(waiting time) = 총 처리 시간 − CPU 버스트 시간
- 응답 시간(response time) = 처음 CPU를 할당받은 시각 − 도착 시각
일반적으로 이용률·처리량은 최대화, 나머지는 최소화하는 것이 목표다.

## FCFS (First-Come, First-Served)
먼저 도착한 프로세스부터 처리하는 비선점형 방식. 구현이 간단하지만, 긴 버스트의 프로세스 뒤에 짧은 프로세스들이 기다리는 호위 효과(convoy effect)가 발생해 평균 대기 시간이 길어질 수 있다.
예: P1=24, P2=3, P3=3 (모두 시각 0 도착, 순서대로) → 대기 시간 0, 24, 27 → 평균 17.

## SJF (Shortest-Job-First)
다음 CPU 버스트가 가장 짧은 프로세스를 먼저 선택한다. 평균 대기 시간 측면에서 최적(optimal)임이 증명되어 있다.
선점형 SJF는 SRTF(Shortest-Remaining-Time-First)라고 한다.
다음 버스트 길이는 알 수 없으므로 지수 평균으로 예측한다: $\tau_{n+1} = \alpha t_n + (1-\alpha)\tau_n$ ($0 \le \alpha \le 1$).

## 우선순위 스케줄링
각 프로세스에 우선순위를 부여하고 가장 높은 우선순위에 CPU를 할당한다 (보통 작은 숫자가 높은 우선순위).
문제점: 기아(starvation) — 낮은 우선순위 프로세스가 무한히 대기할 수 있다.
해결책: 노화(aging) — 오래 기다린 프로세스의 우선순위를 점진적으로 높인다.

## 라운드 로빈 (Round Robin)
시간 할당량(time quantum) $q$ 동안만 실행하고 준비 큐의 끝으로 보내는 선점형 방식. 시분할 시스템에 적합하다.
프로세스가 $n$개일 때 어떤 프로세스도 $(n-1)q$ 시간 이상 기다리지 않는다.
$q$가 매우 크면 FCFS와 같아지고, 너무 작으면 문맥 교환 오버헤드가 커진다. 경험적으로 CPU 버스트의 80%가 $q$보다 짧도록 정한다.

## 다단계 큐와 다단계 피드백 큐
다단계 큐: 준비 큐를 여러 개(예: 전위 foreground — RR, 후위 background — FCFS)로 나누고 프로세스는 한 큐에 고정된다.
다단계 피드백 큐(MLFQ): 프로세스가 큐 사이를 이동할 수 있다. CPU를 많이 쓰면 낮은 우선순위 큐로 내려가고, 오래 기다리면 노화로 올라간다.
MLFQ를 정의하는 매개변수: 큐의 개수, 각 큐의 스케줄링 알고리즘, 승격/강등 기준, 프로세스가 처음 들어갈 큐.
