# 과목별 스터디 모집

## 범위
선택한 과목(Subject) 안에서 모집글을 조회하고 개설한다. 같은 과목이면 교수가 달라도 하나의 목록을 공유한다. 해당 과목의 강좌 중 하나라도 볼 수 있는 로그인 사용자(수강 기록 보유자, 공용 강좌 이용자, 관리자 등 기존 권한 규칙)는 조회·개설할 수 있다. 모집 종료는 개설자만 가능하다.

## 화면
- 새 디자인: 학습 화면의 과목 카드 **스터디 찾기** 또는 강좌 단원 화면의 **이 과목 스터디 모집** → `/study/subjects/:subjectId/groups`.
- 기존 디자인: `/courses/:courseId`의 **스터디 모집** 탭.
- 목록: 모집 중(기본), 모집 종료, 전체. 최신순 10개씩 조회.
- 개설: 제목(2~100자), 소개(10~3000자), 총인원(개설자 포함 2~20명 또는 0=제한 없음), 진행 방식(온라인/오프라인/병행), 시간·기간, 장소·진행 채널(각 2~200자).
- 개설자 이름과 작성 내용은 해당 과목 접근 권한이 있는 사용자에게 공개된다. 이메일·사용자 ID는 반환하지 않는다.
- 모집 종료: 본인이 개설한 모집 중 글에만 버튼을 표시한다. 확인 창에서 확정하며 재개설 상태로 되돌리는 기능은 없다. 종료된 글은 삭제되지 않는다.
- 참여 인원은 개설자 1명과 승인된 신청자 수의 합이다. 개설자는 대기 신청 수와 신청자 명단을 확인하고 승인·거절할 수 있다. 연락처 교환·취약점 추천은 아직 포함하지 않는다.

## API
기본 경로 `/api/v1`:
- GET `/subjects/{subject_id}/study-groups?state=open&offset=0&limit=10`: 권한 확인 후 목록/총개수 반환. state는 open/closed/all, limit 최대 50.
- POST `/subjects/{subject_id}/study-groups`: 개설. owner_id와 subject_id는 서버가 결정하며 임의 입력을 거부한다.
- POST `/subjects/{subject_id}/study-groups/{group_id}/close`: 개설자만 모집 종료. 다른 과목의 ID는 404, 타인의 글은 403. 중복 요청은 최초 closed_at을 유지한다.
- 개설 후 수강 연결이 사라져도 소유자 종료 API는 허용한다. 다만 기존 강좌 화면은 접근 제한되어 해당 상황의 별도 내 모집 관리 화면은 추후 필요하다.

## DB / 배포
`study_groups` 테이블 한 개를 추가한다. subject_id와 owner_id는 각각 subjects/users를 참조한다. 내용과 조건, created_at, closed_at을 저장하며 closed_at이 null이면 모집 중이다.

마이그레이션: `a90dc6c4db81` → `9bbfc5a89a1d`.
운영 배포 시 백엔드 실행 전에 `alembic upgrade head`가 필요하다. 운영 Neon에는 적용하지 않았으며 임시 SQLite에서 기존 head 적용, 자동 생성, upgrade/check/downgrade/upgrade를 검증했다.

## 검증
인증, 강좌 접근 권한, 과목별 목록 분리, 입력값/소유자 위조 차단, 개설자 전용 종료, 반복 종료 요청, 상태 필터와 페이지 조회를 자동 테스트한다. DB·API 외에 프론트 타입 검사, 린트, 빌드를 실행한다.


## 참여 신청과 인원
- 인원 제한 없음 선택 시 capacity=0으로 저장한다. 직접 0을 입력해도 같다. 1명 정원은 허용하지 않는다.
- apply: 과목 접근 권한 보유자만 신청 가능. 개설자·중복 신청·모집 종료·정원 마감은 409.
- cancel: 본인의 대기/승인 신청을 취소한다. 승인된 인원이 나가면 참여 인원이 줄어든다. 모집 중이면 재신청 가능하다.
- applications: 개설자만 이름·상태·신청 시각을 조회한다. 이메일은 노출하지 않는다.
- applications/{application_id}/decision: 개설자만 pending을 approved/rejected로 변경한다.
- 모집 종료 시 승인 명단은 유지하고 대기 신청은 rejected로 처리한다. 종료 후에도 승인된 사용자는 참여를 취소할 수 있다.
- 신청/취소/승인/종료는 부모 스터디 행의 쓰기 잠금을 잡고 처리하여 동시에 승인해도 정원을 넘기지 않도록 한다.
- 추가 테이블 study_applications는 (group_id, user_id) 유일 제약을 가진다. 마이그레이션 `e766111f9118` (부모 `9bbfc5a89a1d`).


## 참여자 전용 공간

개설자 또는 approved 참여자에게만 모집 카드의 스터디 입장을 표시한다. 화면은 `/study/groups/:groupId`, API는 `GET /api/v1/study-groups/{group_id}/space`이다. 서버에서 멤버십을 확인하며 미로그인은 401, 미신청/대기/거절/취소 및 비참여 관리자는 403, 없는 스터디는 404다. 모집 종료 후에도 입장을 유지하고 참여 취소 후에는 접근을 차단한다. 스터디 제목, 과목과 기본 안내만 표시하며 공지·채팅·일정 등 운영 기능은 아직 없다. 별도 테이블 추가는 필요 없다.
