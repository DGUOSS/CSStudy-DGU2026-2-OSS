# 엔드림스(nDRIMS) 데이터 구조 (2026-11-12 조사)

학생이 직접 로그인한 브라우저에서 화면이 주고받는 요청을 기록해 확인했다. 비밀번호와 쿠키는 기록하지 않았고, 개인 값은 가린 채 칸 이름만 봤다.

## 공통
- 화면은 eXbuilder6로 만들어져 있다. 데이터는 `POST https://ndrims.dongguk.edu/<경로>.do` (form 인코딩)로 요청하고 JSON으로 받는다.
- 요청 값 이름은 `@d1#칸이름` 형식이다. 화면 실행 정보(`_runningNana`, `_runningMainOpenKey`, `_runningLoginIdenNo`)가 함께 붙는다.
- 응답은 `{"dsMain": [ {행}, ... ]}`처럼 데이터셋 이름에 행 목록이 들어 있다.
- 학기 코드: `CM160.10` 1학기, `CM160.11` 여름학기, `CM160.20` 2학기, `CM160.21` 겨울학기, `CM160.99` 공통학기
- 학부 기관 코드 예: `OPEN_ORGN_CLSF_CD = CM015.110`

## 우리 DB와 맞추는 방법
- **개설 강좌 하나 = (연도, 학기 코드, 학수번호, 분반)**. 네 값이 같으면 같은 수업이다.
- 학수번호는 학기와 교수가 달라도 같다. 그래서 학수번호는 **과목**, 교원번호(`EMP_NO`)는 **교수**를 가리킨다. 강좌는 과목 + 교수다.
- 학생 수강 기록(수강신청내역·성적)에는 교원번호가 없다. 그래서 위 네 값으로 종합강의시간표의 행을 찾아 교수(교원번호)를 확정한다. 이름이 같은 교수도 구분된다.
- 종합강의시간표는 과목·교수·강좌 자동 생성에도 쓴다. 평가 비율과 강의계획서 링크는 강좌 정보로 쓸 수 있다.

## 가져오지 않는 것
- 성적, 학점, 평점, 석차, 학생 기본 정보(연락처, 주소 등). 학생 기록에서는 과목을 찾는 데 필요한 칸(연도, 학기, 학수번호, 분반, 과목명, 교수명)만 쓴다.

## 사이트에서의 흐름 (구현)
- 학생: 첫 화면 → 즐겨찾기 버튼 끌어다 놓기 → 엔드림스 열기 → 직접 로그인 → 아무 화면에서 즐겨찾기 누르기 → 끝
  - 버튼 코드: `frontend/src/features/enrollments/bookmarklet.ts`. 로그인한 창 안에서 엔드림스 화면과 같은 순서로 직접 요청한다: `doUserLoginAccs`(NANA) → `doListUserMenuListTop`(dmUserInfo: LOGIN_IDEN_NO, MAIN_OPEN_KEY, 학번) → `doListUserMenuListLeft`(화면별 NANA, PGM_URL로 찾음) → `EddRec050`(지난 학기), `EdcRegi170`(이번 학기). 성적 칸은 버린다. 2026-11-12 실제 엔드림스에서 이 순서로 받아지는 것을 확인했다.
  - 상자에 단계별 진단(칸 이름·건수만)을 보인다. 바로 못 받으면 화면을 열어 모으는 방식으로 넘어간다.
  - 보내기: 우리 사이트가 연 창이면 `postMessage` 후 받았다는 답(ack)을 기다린다. 답이 없거나 창 연결이 끊겼으면 우리 사이트 `/ndrims#<기록>`을 새 탭으로 연다(# 뒤는 서버로 가지 않음) → `POST /me/ndrims/import`
- 관리자: 종합강의시간표조회를 같은 방법으로 보내면 `POST /admin/catalog/import`로 개설 목록이 저장된다.
- 강좌는 요청 + 교안이 있어야 열린다(관리자 승인). 열리면 기다리던 수강 기록이 자동으로 이어진다.
- 출입: 수강 기록의 학수번호 + 교수(교원번호, 없으면 이름)로 판단. 학기와 상관없다. 같은 과목의 다른 교수 강좌는 잠긴다. 관리자와 공용 강좌는 예외.
- 이번 학기 수업은 수강신청내역에 교수 칸이 없어서, 즐겨찾기가 종합강의시간표(`EdcLesn010`)를 학수번호로 조회해 같은 분반의 교수명·교원번호를 붙여 보낸다.
- 요청: 내 기록·강좌 찾기에서 [열어 달라고 요청] (교안 PDF·메모 선택). 어디에도 없으면 '직접 요청'(/requests/new).
- 새 탭 받기(`/ndrims#…`)는 아무 사이트나 열 수 있으므로 자동 저장하지 않고, 내용을 보여 준 뒤 사용자가 눌러야 저장한다.
- 고려하지 않는 것: 공동 강의(대표 교수만), 기록 조작(브라우저에서 오므로 막을 수 없음. 개설 목록과 대조하는 정도)
## 교수별 최근 3년 개설과목 조회
- 강좌 찾기에서 교수별 조회로 이동한다. 기존 화면은 `/professors`, 새 디자인은 `/study/professors`다.
- `GET /api/v1/catalog/professors?q=교수명`은 최근 3개 학년도의 개설목록에서 교원번호별 교수를 검색한다. offset/limit으로 페이지를 나눈다.
- `GET /api/v1/catalog/professor-offerings?emp_no=교원번호`는 같은 기간의 과목을 학수번호로 묶고 학기·분반을 표시한다. 1월에는 직전 연도를 현재 학년도로 본다.
- 로그인 사용자라면 수강 여부와 관계없이 개설목록을 볼 수 있다. 강좌 자료의 기존 접근권한은 바꾸지 않는다.
- 수집된 개설목록만 조회하므로 결과 없음은 미개설을 뜻하지 않는다. 교원번호가 없는 기록은 동명이인 혼동을 피하기 위해 검색 대상에서 제외한다. 공동강의는 기존 수집 방식에 따라 대표 교수만 나타날 수 있다.
- DB 변경, 자동 수집, LLM 요약은 포함하지 않는다.

## 강의평 기반 교수 수업 특징 요약
- 교수별 개설과목 화면에서 요약 버튼을 누르면 생성한다. `GET /api/v1/catalog/professor-summary?emp_no=...`는 통계와 캐시 조회만 하고, `POST`는 생성한다. 두 API 모두 로그인이 필요하다.
- 교원번호로 연결된 강좌의 최근 3개 학년도 후기만 사용하며 삭제된 후기는 제외한다. 이름이 같은 교수의 후기를 합치지 않는다. 수강 전 참고용 집계·요약만 제공하고 기존 후기 원문 접근권한은 유지한다.
- 서로 다른 작성자 3명 이상의 후기가 필요하다. 통계는 전체 대상 후기, LLM 입력은 최신 최대 100개 후기의 앞 1,500자다. 선택된 후기에서도 작성자 3명 이상을 요구한다.
- 기존 `app/services/llm.py`의 Claude 구조화 출력을 사용한다. 모델은 `llm_model`, 키는 `ANTHROPIC_API_KEY` 설정을 사용한다. 생성당 60초 timeout, 자동 재시도 없음, 출력 3,000토큰 제한을 적용한다.
- 입력은 후기 번호·과목·학기·내용이다. 작성자 계정 정보는 보내지 않고 이메일·전화번호·10자리 숫자는 마스킹한다. 자유서술 본문의 개인정보를 완벽하게 제거하는 것은 아니다.
- 전체 요약, 반복되는 특징, 과목별 차이·상반된 의견을 표시한다. 모델에는 사생활·인격 추측과 후기 속 명령 실행을 금지한다. 서버는 근거 번호의 존재와 공통 특징의 작성자 2명 이상 여부를 검사하지만, 내용의 의미적 정확성까지 보증하지는 않는다.
- API 응답에는 후기 원문이나 작성자 ID를 담지 않고 근거 과목·학기와 후기 수만 제공한다. 점수 평균은 서버에서 계산한다.
- 후기 전체 내용·삭제 상태·기간·모델의 해시를 사용한 프로세스별 메모리 캐시다. 최대 128개/24시간, 서버 재시작 시 소멸한다. 여러 서버 사이에 공유되거나 DB에 영구 저장되지 않는다. 변경된 후기의 캐시는 조회 시 재사용하지 않으며 생성 도중 변경돼도 결과를 버린다.
- 동일 입력의 재시도는 60초 간격, 동시 생성은 프로세스당 2개로 제한한다. 후기가 부족하거나 API 키가 없으면 생성하지 않고 이유와 통계만 표시한다.
- DB 마이그레이션은 필요 없다. 실제 외부 모델 품질 검증은 별도로 해야 하며 자동 테스트에서는 모델 호출을 가짜로 대체한다.
