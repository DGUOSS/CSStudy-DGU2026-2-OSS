# 팀원 소개: 오개념 반례 실험실

## 한 문장으로

학생이 문제를 틀렸을 때 바로 해설만 보여주는 대신, **그 오답을 고른 이유를 확인할 수 있는 짧은 문제를 하나 더 제시하고**, 두 답을 함께 보며 교안의 어느 규칙을 복습할지 알려주는 기능입니다.

## 왜 필요한가요?

같은 오답에도 이유가 다를 수 있습니다. 규칙을 잘못 이해했을 수도 있고, 문제를 급하게 읽었거나 우연히 잘못 눌렀을 수도 있습니다. 기존 문제의 정답만 보여주면 이 차이를 알기 어렵습니다. 이 기능은 **다른 상황에도 같은 규칙을 적용할 수 있는지** 확인해 학생에게 더 적절한 설명을 주려는 아이디어입니다.

여기서 ‘반례’는 학생이 머릿속에 세운 잘못된 규칙이 다른 입력에서는 통하지 않는다는 것을 보여주는 사례입니다. 학생의 생각을 단정하는 판정기가 아닙니다.

## 실제 화면에서는 이렇게 진행됩니다

기초프로그래밍의 `printf` 문제를 예로 들면:

1. 원래 문제: `printf("[%03d]", 7);`의 출력 결과를 고릅니다. 정답은 `[007]`입니다.
2. 학생이 `[7]`을 고르면, 시스템은 “출력 폭을 무시하고 숫자만 출력된다고 생각했을 수도 있다”는 **가설**을 세웁니다.
3. 이어서 `printf("[%03d]", 20);`의 결과를 묻습니다. 정답은 `[020]`입니다. 숫자가 바뀌어도 세 칸을 채우는 규칙이 적용되는지 확인하는 문제입니다.
4. 두 번째 문제까지 틀렸다면 “이 규칙을 다시 확인해 보세요”라고 안내하고, 두 번째 문제는 맞혔다면 “처음 오답만으로 오개념을 확정할 수 없습니다”라고 안내합니다.
5. 해설과 함께 **교안 32쪽의 근거**를 표시하고, 해당 쪽의 추출된 텍스트를 펼쳐 볼 수 있습니다.

```text
원래 문제 → 고른 오답에 맞는 확인 문제 → 두 답을 비교한 안내 → 교안 근거와 복습 위치
```

확인 문제는 학생의 **숙련도 점수를 바꾸지 않습니다**. 학습을 돕기 위한 추가 확인이며, 결과는 강좌의 숙련도 탭에서 다시 볼 수 있습니다.

## 문제의 정확성은 어떻게 관리하나요?

확인 문제는 원래 문제의 **특정 오답 선택지**에 연결됩니다. 관리자 검토 화면에서 원래 문제, 오답, 추정한 생각, 확인 문제, 정답, 해설과 교안 근거를 함께 살펴볼 수 있습니다. **승인된 문제만 학생에게 표시**됩니다. 승인할 때 지정한 교안 쪽에 근거 문장이 실제로 있는지도 검사합니다.

현재 데모에는 실제 교안을 토대로 만든 확인 문제 3개가 있습니다. 그중 1개는 승인되어 학생 흐름에서 볼 수 있고, 2개는 관리자 검토를 기다리는 초안입니다. **AI가 문제를 자동 생성하는 기능은 아직 없습니다.** 나중에 AI를 쓰더라도 초안 생성까지만 맡기고, 학생에게 공개하기 전에 사람의 검토를 거치는 방향을 제안합니다.

## 어디서 체험하나요?

- [브랜치 웹 미리보기의 독립 시범 화면](https://dgu-study-git-feat-misconception-probes-kachipuchipas-projects.vercel.app/lab/misconception): 답에 대한 확신도 선택, 확인 문제, 결과, 추가 연습을 볼 수 있습니다. 현재 Vercel 로그인이 필요하며 이 화면의 답은 저장되지 않습니다.
- **실제 강좌 풀이에 붙은 기능**: [로컬 데모 실행 방법](DEMO.md)에 따라 별도 데모 DB로 체험할 수 있습니다. 원래 문제, 확인 문제, 결과 저장, 관리자 승인까지 연결되어 있습니다.

브랜치 웹 미리보기의 API는 아직 운영 백엔드를 가리킵니다. **온라인 미리보기에서 로그인이나 문제 풀이를 시험하지 말고**, 별도 데모 백엔드와 DB를 연결한 뒤 팀원에게 통합 체험 링크를 공유해야 합니다. 이 브랜치는 `main`에 병합하지 않았습니다.

## 회의에서 결정할 내용

1. 오답을 고른 학생에게 확인 문제를 **바로 이어서** 보여주는 흐름이 학습에 도움이 되는가?
2. 결과 문구가 학생의 생각을 단정하지 않으면서 충분히 이해하기 쉬운가?
3. 처음에는 **사람이 만든 소수의 문제**로 시작할지, AI 초안 생성을 다음 단계로 둘지?
4. 적용 범위를 한 강좌의 검증된 문제부터 넓혀 갈지?

현재 버전은 아이디어 검토용 데모입니다. 여러 문제에서의 진단 정확도 평가, AI 자동 생성, 약점을 표시한 PDF 제작은 아직 구현하지 않았습니다.
