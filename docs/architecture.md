# 구조와 역할

## 현재 범위

사용자가 PDF와 실제 배운 범위를 등록하면 학습·복습을 지원하고,
과제·시험을 반영해 주간 부담을 분산하는 웹 서비스입니다.
eClass 자동 수집과 확장 프로그램은 현재 구현 범위에서 제외합니다.

## 구성

웹 화면 → FastAPI → PostgreSQL 및 파일 저장소

FastAPI 안에서 AI·계산 담당자의 Python 모듈을 호출합니다.
현재 구현된 기능은 `/health`뿐이며 DB·파일 저장·인증·AI·배치는 미구현입니다.

| 경로 | 책임 |
| --- | --- |
| `backend/app/api` | HTTP 요청과 응답 |
| `backend/app/schemas` | 공통 요청·응답 형식 |
| `backend/app/models`, `db` | DB 모델, 연결, 저장 |
| `backend/app/services` | 기능 흐름과 모듈 연결 |
| `backend/app/ai` | 자료 텍스트 추출, 문제 생성·품질 검사 |
| `backend/app/scheduling` | 부담도, 복습일, 주간 배치·주중 반영 |
| `frontend` | 사용자 화면 |

## 데이터 설계 원칙

- 자료 파일, 배운 범위, 날짜별 일정, 실제 학습 기록을 분리합니다.
- 배운 날짜와 앱에 등록한 날짜를 구분합니다.
- 계획 조회는 저장된 결과만 반환하고 재계산은 별도 작업으로 수행합니다.
- 사용자 소유권은 서버에서 검사합니다.
- 문제 조회에는 정답을 포함하지 않고 제출 후 채점 결과를 반환합니다.
- 고정·완료 일정과 실제 복습 기록을 재배치로 덮어쓰지 않습니다.
- PDF 및 비밀키를 Git에 올리지 않습니다.

## 후속 합의

DB 관계, 인증 방식, 파일 저장소, 문제·계산 함수 입출력은 팀과 정합니다.
pyBKT 사용 여부와 부담도 방식은 발표 자료와 3차 방향성의 불일치를 정리한 뒤 확정합니다.
주중 여유가 없을 때의 처리, 장기 과제 시작 기준, 시험 모드도 별도 설계가 필요합니다.
