# 팀 프로젝트(팀플) 라벨

과목마다 팀플 유무를 배지로 보인다. 같은 과목이라도 교수·학기마다 다르므로 라벨은 **(강좌 = 과목+교수, 학기)** 단위다.

## 근거와 우선순위
1. **강의계획서** (엔드림스) — 교수가 공지한 내용이라 가장 먼저 따른다.
   - 계획서 글을 규칙으로 판정한다(`backend/app/features/team_project/service.py`의 `classify_syllabus`).
     - 있음: "팀 프로젝트", "팀플", "조별", "그룹 과제", "team project" 등
     - 없음: 같은 문장에 "없음", "하지 않", "0%", "no team project" 등
     - 언급 없음: 위 표현이 없음 → 배지 "팀플 언급 없음"
   - 판정 결과와 근거 문장만 `catalog_offerings`에 저장한다(`team_project`, `team_evidence`, `syllabus_checked_at`). **계획서 원문은 저장하지 않는다.** 시간표를 다시 가져와도 지워지지 않는다.
   - 분반이 여럿이면 하나라도 "있음"이면 있음.
2. **후기 응답** — 후기 작성 시 "팀 프로젝트가 있었나요?"(있었어요/없었어요/답하지 않음). 그 학기 수강 기록으로 쓴 후기만 그 학기에 센다. 계획서가 없거나 언급이 없는 학기는 다수결로 정한다.

| 계획서 | 후기 | 라벨 |
|---|---|---|
| 있음 / 없음 | 무엇이든 | 계획서대로 (후기 수는 함께 표시) |
| 언급 없음 · 없음(미수집) | 있었다 > 없었다 | 있음 |
| 언급 없음 · 없음(미수집) | 없었다 > 있었다 | 없음 |
| 언급 없음 | 동률/없음 | 팀플 언급 없음 |
| 미수집 | 동률/없음 | 표시 안 함 |

## 화면
- 강좌 찾기(개설 목록): 그 학기·그 교수 분반 묶음의 라벨
- 과목의 강좌 목록, 강좌 화면 제목 아래: 가장 최근 학기 라벨
- 강좌 정보 탭: 학기별 라벨과 근거(계획서 문장 / 후기 n명 중 m명)

## API
- `GET /api/v1/courses/{id}/team-project` — 학기별 라벨. 수강 기록 없이도 볼 수 있다.
- `POST /api/v1/admin/catalog/syllabi` (관리자) — `{rows: [{year, sem_cd, sbj_no, dvcls, text}]}`. 개설 목록에 있는 행만 판정·저장한다.

## 남은 일: 계획서 가져오기
엔드림스 종합강의시간표의 `PLAN_URL`은 지금 비어서 온다(배포 DB 2,543행 모두 빈 값). 계획서는 별도 화면(강의계획서 조회)에서 받아야 하는데, 그 화면의 요청 경로·값 이름은 아직 조사하지 않았다. 조사되면 즐겨찾기(`bookmarklet.ts`)가 관리자 화면에서 개설 강좌별 계획서 글을 받아 위 API로 보내면 된다. 조사 방법은 `docs/NDRIMS.md`와 같다(로그인한 브라우저에서 화면 요청 기록, 개인 값은 보지 않음).

## 에브리타임을 쓰지 않는 이유
에브리타임 강의평은 로그인해야 보이고, 이용약관이 자동 수집과 무단 복제·재게시를 금지한다. 다른 사람이 쓴 글을 가져와 다시 보여 주는 것은 저작권 문제도 있다. 대신 우리 후기에 같은 질문을 넣어 수강 기록이 확인된 학생의 응답을 모은다.
